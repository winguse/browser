How it Works

sequenceDiagram
    box Client Side (Browser Process)
    participant B as Browser Tab
    participant G as Gecko (WASM)
    participant WC as Wisp Client
    end
    box Server & Internet
    participant W as Wisp Proxy Server
    participant D as DNS Server
    participant R as Target Web Server
    end

    Note over B, G: UI Rendering
    B->>G: User interaction (click, scroll)
    G->>B: Render updates to Canvas WebGL

    Note over G, WC: Network Traffic
    G->>WC: Virtual Network Socket Connection

    WC->>W: Establish WebSocket (Wisp Protocol)

    W->>D: 1. DNS Query (Requested by Client)
    D-->>W: IP Address

    W->>R: 2. TCP Handshake (Proxy forwards bytes)

    Note over G, R: End-to-End Encryption
    G->>R: 3. TLS (https/wss) Handshake (Wisp only sees encrypted bytes)
    G->>R: 4. HTTP Request (Encrypted)
    R-->>G: HTTP Response (Encrypted)

    G->>B: Canvas WebGL update (Render Page)
